# Figure Specifications — the five not produced by `tools/make_figures.py`

Written 2 October 2026. Seventeen figures are generated by
`python tools/make_figures.py`. These five are not, for stated reasons.

**House style, so these match the generated set:** one sans-serif family
throughout, 8–8.5 pt axis labels, 9.5 pt bold panel titles, 300 dpi minimum,
PNG at 300 dpi. Colourblind-safe: viridis for sequential, RdBu for diverging.
Every map carries a scale bar, north arrow, legend and graticule.

**PNG only, 300 dpi** — changed 3 October 2026; the generated set no longer
emits PDFs. Review standard for all figures: `docs/FIGURE_REVIEW_PROTOCOL.md`.

**Output naming:** `outputs/figures/fig01.png` … matching the generated files.

## Figure 1 — Study area, three panels · **QGIS**

**Why QGIS:** three nested extents with labelled towns and named rivers.
Placing labels so nothing collides is interactive work; a print layout does it
properly and matplotlib does not.

**Panel A — location.** India with Maharashtra highlighted, Maharashtra with
Chandrapur highlighted. GADM ADM1 and ADM2.

**Panel B — the district.** `data/boundary.geojson` outline, `data/rivers.geojson`
(HydroRIVERS, 776 features) styled by `ORD_STRA` so higher-order channels render
thicker. Label the Wardha and Wainganga. Add major settlements as points with
labels — derive from `data/population.tif` where density exceeds
400 people/km², or use an external gazetteer and say which.

**Panel C — the analysis grid.** The 450 × 422 grid over the boundary, with the
123,555 in-district cells shaded and the remainder left white. At full
resolution the grid reads as a solid block, so show a zoomed corner inset at
true cell size instead, labelled "≈0.31 × 0.30 km".

**Caption facts:** 11,412.5 km² analysed against 11,443 km² official, a 99.7%
match that independently confirms the boundary mask and the per-row cell-area
arithmetic.

## Figure 3 — Preprocessing chain · **diagram tool**

**Why not matplotlib:** box-and-arrow diagrams drawn in matplotlib look
hand-rolled. draw.io, Inkscape or PowerPoint will look better in less time.

**Flow, left to right:**

```
SEVEN SOURCES                 COMMON GRID                 SCORED CRITERIA
GADM boundary        ─┐
HydroRIVERS v1.0     ─┤                                   slope        0.2254
CHIRPS v3.0 annual   ─┼─► build 450 × 422 grid ──┐        rainfall     0.4285
HydroSHEDS → slope   ─┤    from boundary bbox     │       drainage     0.0932
SoilGrids TEXMHT     ─┤                            ├─►    soil         0.1535
MODIS MCD12Q1        ─┤    reproject onto grid     │      land cover   0.0597
WorldPop 2020        ─┘    bilinear | nearest      │      settlement   0.0397
                                                   │
                           mask to district ───────┤
                           fill rim gaps ──────────┘
                           (soil 2.2%, pop 2.0%,
                            slope 1.1%, lulc 0.1%,
                            rainfall 0.0%)
```

**Annotate two things, because both are correctness points:**

- **Resampling splits by data type.** Continuous layers bilinear; categorical
  layers nearest neighbour — averaging class 4 and class 6 would invent class 5.
- **Two criteria are derived, not downloaded.** Drainage density from river
  lines densified to 100 m and convolved with a 2.5 km circular window;
  settlement proximity from an exact distance transform over cells above
  400 people/km².

A linear pipeline showing where this work stops and practice begins. The honest

```
  │                  4 methods     │  │                                   │
  │                  528.5 km²     │  │                                   │
  └────────────────────────────────┘  │                             │     │
                                      │                             ▼     │
                                      │  ownership      engineering       │
                                      │  and cost    ─► design      ─►    │
                                      │  enquiry                   final  │
                                      │                           siting  │
                                      └───────────────────────────────────┘
```

**Get the consensus box's numbers right. They are different quantities from
Fig. 22's.**
- "15 sites picked by all 4 methods": each method extracts its own shortlist,
  the shortlists are matched within 2 km, and 15 of the 35 distinct locations
  appear in all four (`python consensus.py`, paper Table 17).
- "528.5 km²": the area all four methods class as High (Fig. 16(a)).
- Fig. 22's "22 of 25" is a third quantity: how many sites on the **baseline**
  shortlist sit in cells all four methods class as High.

Use the first two in this box. Do **not** write "15 unanimous sites"; it reads
as contradicting Fig. 22's 22.

**Shade the two halves differently and label them.** A reviewer who sees the
model presented as the whole pipeline will distrust it; one who sees the
boundary drawn honestly will not.

**Caption:** the model narrows 123,555 cells to 25 candidates and, via
cross-method consensus, to 15 that every method selects. Everything downstream
of that remains to be done.

## Data available for the QGIS figures

All in `outputs/`, regenerate with `python exports.py` and
`python consensus.py --write`:

| File | Contents |
|---|---|
| `rwh_suitability_classified.tif` | 1 Low / 2 Medium / 3 High |
| `rwh_suitability.tif` | continuous 0–1 composite |
| `rwh_sites.geojson` | 25 points with `rank` and `score` |
| `rwh_sites.csv` | same plus per-criterion scores, weighted contributions and raw values |
| `consensus_algorithms.csv` | 35 locations, Borda score, how many methods chose each |
| `drainage_density.tif`, `curve_number.tif`, `runoff_depth.tif`, `runoff_coefficient.tif` | derived hydrology |

Source layers are in `data/`. Everything is EPSG:4326 except `slope.tif`,
`soil_texture.tif` and `population.tif`, which are EPSG:32644 and are reprojected
at run time.
